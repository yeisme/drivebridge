# 筛选、身份信息与菜单交互改进

本轮对应第三轮六处浏览器标注，实施归 `drivebridge-interaction-polish-v2`。继续复用 Base UI、TanStack Table 与现有深浅主题，不改变接口、权限、Key 生命周期或数据归属。

## 用户可见变化

| 标注 | 实现 |
| --- | --- |
| 更多筛选展开后错位 | 改为高级筛选浮层；标题、存储连接、日期和完成按钮分区，关闭或选择条件不会推动指标布局。日期摘要留在触发器旁。 |
| 审计用户 ID 太长 | 优先显示当前可见用户名，未知身份回退到类型；ID 显示前 8 位和后 6 位，完整值保留在提示和导出。 |
| 审计动作英文 | 常见读取、上传、Key、团队、授权等动作使用中文；未知动作显示“其他操作”，提示保留原动作码。 |
| 工作区菜单拥挤 | 身份、工作空间、常用入口、体验身份、退出分区；所有入口左对齐，体验身份标签单独占行。 |
| Key 表格互相覆盖 | 名称使用自然高度布局，用户角色独立显示，团队名称可省略；行内保留复制、详情与更多。轮转、启停、吊销、删除、改名进入菜单，原确认流程不变；合并重复搜索。 |
| 设置右侧无用说明 | 删除“使用偏好”说明卡和顶部冗余说明，以外观、个人资料、账号信息大纲替代；内容宽度不足 800px 时大纲置顶。实际主题、密度、动效设置保留。 |

可搜索选择器在没有实际选中值时显示展开箭头；必选且不允许空值的选择器不显示清除按钮。可选字段及头像仍能清空。高级筛选复用原即时生效语义，原始查询和导出字段不翻译。

## 权限与可访问性

身份名称只取当前已经授权的治理投影、本人资料和可见机器人列表，不为补全名字额外查询全局用户。用户与机器人即使 ID 相同也分别匹配，caller 不用于认证身份展示。

菜单采用原语的键盘、分层 Escape 和焦点管理；浮层内部的下拉关闭后，可以继续 Tab 到完成按钮或退出外层浮层。Key 的危险动作仍需原确认，最后一把有效 Key 的保护继续由服务端执行，截图不包含明文 Key。

设置大纲滚动现有内容区并聚焦分区，不写入 hash，不丢弃未保存资料；滑到页面底部时保持最后分区高亮。浏览器存储失败提示留在外观设置旁。

## 共用表单布局修复（2026-09-23）

机器人授权的新反馈揭示了同一类问题：旧 `.checkbox`、`.checkbox-label` 与嵌套字段没有一致的布局规则。共用弹窗现按直接子控件类型识别字段：普通输入和下拉的标签在上，间距 8px；勾选项横排，间距 12px；触屏勾选标签至少 44px。Base UI 生成的提交用 checkbox/radio input 不参与普通字段匹配，避免再次抢占布局。

机器人授权使用 480px 弹窗和独立操作选项组；连接存储、机器人授权、批量签发和新建 Key 补齐底部取消/提交区。名称中文化，不改变默认读取权限、提交参数或后端规则。布局范围限定 AppDialog 内，保留复杂预览和详情的原有布局。
