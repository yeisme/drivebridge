## 1. 产品问题与定位

一个人有多个网盘、多个设备和多个 Agent。文件浏览、检索、整理、接收产物与判断“究竟改了什么”应在同一工作台完成。普通文件操作必须在没有接入 Agent、没有模型服务时可用；Agent 取得的是某个目录内的具体动作，不是用户整块网盘的所有权。

第一交付目标是“个人空间、多 Agent、文件与创作资料并重”的桌面及手机 Web 客户端。保留既有团队、租户与分享能力，通过有权限的兼容入口承载；不把它们放回个人导航的主叙事。原生桌面/手机宿主、系统相册和后台任务是保留的后续切片，Web 原型不证明这些能力可用。

前端采用整体壳层与页面重建。首先建立旧能力保护清单，清理旧入口、页面编排和冲突样式，再在现有 React/TypeScript/Vite 工程内实现新版；文件协议、身份、恢复逻辑和安全阅读器经过审查后复用。

## 2. 基线与冲突优先级

设计依据是 OpenDesign 项目 `drivebridge-personal-agent-workspace`，不是本地 v9.2 副本。本轮冻结证据为 `temp/integration-test-runs/20261007T153519Z-539b03a2/`：46 个实际页面加载资源双读一致，桌面/手机导航观察均无页面异常与横向溢出；仅证明列出的原型页面，不证明业务、未访问动态路径或完整全站验收。原型显示 v48 及 v49/多笔记资源，版本定位以摘要为准。历史 v33/v37/v39 和 v36 未核实记录保留。远端后续变化单列，不自动扩展范围。

优先级：当前用户要求 → 本 PRD 与 owner 安全/兼容约束 → 已记录的当前原型截图和资源摘要 → 历史原型。原型有演示缺口时以本规格补齐。所有额外设计决定在下表及 UI 文档中显式列出。

| 决定 | 依据与处理 |
| --- | --- |
| 单人多 Agent 为默认体验 | 当前原型的身份、导航、接入表单；保留已有团队治理的独立兼容入口 |
| 首先清理旧前端 | 当前用户明确要求；不删除用户数据、上传恢复记录、权限逻辑和未迁移能力 |
| 暂不新增全局“AI 聊天”主菜单 | 当前原型无该菜单；先交付按上下文使用 Agent、计划和产物；历史内置助手要求保留为后续切片 |
| 新 Agent 默认长期、默认仅勾选读取 | 用户明确要求；expiry_mode=never，expires_at=null；duration 支持 1/24 小时、7/30/90/365 天。旧 `/agents` 默认 7 天/最长 30 天不变；验证与轮转不续期 |
| Agent 分组与置顶 | 个人组织数据存服务端，跨设备可回读，revision 冲突需重读；删组仅解绑，不撤销、不改变文件权限 |

| 手机与桌面同等设计 | 手机底部首页/文件/Agent/任务/我的；其他入口通过侧栏或“我的”进入 |
| 共享与领域采纳单独表达 | 文件已收件、归档、下载、接收及 Scaena 等领域采纳是不同事实 |

## 4. 角色与关键用户旅程

| 角色 | 需要完成的事 | 成功信号 |
| --- | --- | --- |
| 个人文件用户 | 找文件、上传、阅读、整理与跨存储复制 | 固定文件/版本可回查，断线后能恢复原操作 |
| 创作者/研究者 | 项目素材、文档、模板、资源包与产物放在一起 | 集合不复制文件，引用能定位来源版本 |
| 同一用户的多个外部 Agent | 在明确授权内读取、提交建议与交回产物 | 每个身份有独立范围、期限、记录和撤销 |
| 手机上审阅的人 | 收件、看计划、确认、查看结果 | 不靠 hover 或桌面宽表完成核心路径 |
| 既有管理员/团队用户 | 继续访问已有治理能力 | 旧链接和授权合同可用，个人模式不借此升权 |

标准流程：选择上下文 → 复制受权固定引用和接入配置，由外部客户端自行发起调用 → 查看计划与影响 → 人类确认必要动作 → 执行/恢复 → 检查固定版本结果。回答、建议、计划、批准、实际修改、领域采纳分别显示。

首条真实本地闭环：fixture 登录 → 上传文件 → 刷新 → 打开固定版本 → 创建仅此目录的 Agent → 受限产物上传至收件 → 人类预览并归档 → 原 operation 与版本均可回读。源码、模拟 UI 与真实本地 HTTP+DB 证据分开记录。

## 5. 状态与产品规则

1. 文件：来源观察、受管副本、当前版本、历史版本、离线副本分别表达。预览、复制引用和分享保持选定版本；恢复历史内容创建新版本。
2. 上传：摘要计算、发送、耐久接收、验证、发布五阶段。发送 100% 不能显示“已保存”。中断先查询原键/原 operation；只恢复未完成项。
3. 计划：预览修订和影响摘要绑定确认；上下文、策略、版本、授权变化使原确认失效。部分成功保留每项回执；补偿是新计划。
4. Agent：授权状态、最近连接观察、单次调用结果是三列事实。保存授权不自动探测、不执行；过期/撤销立即禁止新动作，正在写入在发布前复检。新授权 never/duration 显式持久化；duration 从服务端签发或期限修改成功计时，检查、禁用/启用和轮转不续期。禁用、撤销、轮转、期限修改须 revision 校验；轮转保持 grant 身份和期限并使旧凭据立即失效；过期/撤销后重新接入建新 grant。旧缺失期限不解释为永久；不得用远期日期替代长期。
9. Agent 卡片上的分组和置顶绑定本人服务端数据；与导航折叠等本机偏好分开。删除组原子解绑保留置顶与授权，刷新/跨设备不丢组织状态。任务进度取原 Operation/Plan，不凭会话内数组编造进度。
5. 收件：已上传 → 待文件验收 → 已接收/拒绝 → 归档结果。文件验收不宣称创作内容已通过领域审核。来源自述与服务端实际 Agent 身份并列。
6. 内容：查询不自动启用分析，不自动付费；范围、覆盖、索引水位与观察时间可见。标签建议不会覆盖人类标签。
7. 资源：保存、格式检查、安全检查、安装、调用是不同事实。检查某版本的结果不能沿用到新版本；不执行文件中指令。
8. 所有页面覆盖 loading、empty、ready、partial、stale、forbidden、offline、unsupported、error。权限错误有明确退出/返回动作，不无限转圈。
