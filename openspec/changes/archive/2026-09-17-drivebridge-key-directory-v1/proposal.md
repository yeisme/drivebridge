## Why

Key 列表缺少稳定辨识、账号映射和命名操作；治理模式下个人也需要看到自己的登录凭据元数据。

## What Changes

- 新增只返回元数据的 Key 目录及标签修改接口。普通用户及治理模式仅能访问本人的 Key；非治理管理员保持既有全局管理范围。
- 返回所属用户 ID、名称及当前登录标识，不返回哈希或凭据。
- Key 始终绑定原用户，团队与空间权限仍由既有治理合同决定，不允许通过重命名重绑身份。

## Capabilities

### New Capabilities

- `key-directory`: 凭据辨识及用户映射。

## Impact

fit：身份和凭据元数据归服务端；展示归 client。新增接口兼容旧 users 合同，无数据库迁移。回滚前端入口与新路由即可。
