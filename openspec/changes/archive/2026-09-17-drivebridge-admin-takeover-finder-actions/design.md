## Decisions

用户名是操作确认而非登录凭据：必须先通过现有会话/Key 认证且拥有平台管理员角色，保留 CSRF、confirm、expected_revision 和不能操作本人约束。名称在写入事务中与目标用户精确比对；旧 proof 路径保持。

只有冻结/归档导致最后职责缺失时才允许接管。清单包含租户管理员、团队管理员和网盘数据负责人；名称、目标和角色排序后计算摘要，提交必须匹配重新计算的清单。接管只授予执行者列出的缺失职责，保存必要成员关系并审计，随后重新执行原约束与归档事务。任何失败一并回滚。旧接口仍不隐式接管。

零字节上传不再需要分片，Complete 创建空组装文件。加密空对象写入长度为零但含 GCM 认证标签的最终帧，读取器只允许首次零长度帧并校验尾部。非空格式和元数据合同保持不变。

## Compatibility and rollback

HTTP 新字段均可选，旧 Key 确认方式、旧上传及权限检查继续有效；用户明确授权了新的确认与接管语义。数据库无新增字段。空加密文件沿现有认证帧编码，旧非空数据兼容；旧读取器不支持新空文件，因此回退 UI 可以关闭入口，但服务端需保留空文件读取支持。职责接管为明确用户授权的状态变更，不以代码回退撤销已完成操作。

隔离预览更新复用 internal fixtures 的显式 ResumeDemo 选项；必须无进行中任务；默认要求无文件对象，显式 KeepStorage 可保留已有连接和文件，但原 fixture 存储进程必须持续运行。实例密钥、数据库检查点保持私有并由操作脚本生成，身份和目录 ID 不改变。此路径仅用于隔离本地体验，不用于真实部署。

## Validation

Go 测试覆盖错误名称、非平台用户、旧约束、变化的接管摘要、事务无部分角色授予、接管审计、零字节普通/加密上传与下载、同名拒绝和 fixture 身份保留。复用 scripts/check.py 保存通过与失败证据。
