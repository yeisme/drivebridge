# 团队页面与后端对接

团队列表使用 /governance/teams 分页投影。详情为概览、成员、网盘、权限、活动、设置，沿用绿色令牌和现有原生组件；短编辑为右侧抽屉，危险操作用 impact 查询后确认。客户端按服务端 actions 呈现能力，写入仍由服务重新鉴权。

路由基于既有 hash，#/teams/{id}/{tab}?tenant 指向团队详情，#/drive/{id}?tenant&team 指向网盘。分享 #share 格式保留。切换租户或空间重新挂载隔离工作区，旧请求因 context revision 失效；同团队 tab 使用独立路由状态，快速历史导航不清空有效详情。团队概览的媒体使用显式 per-file tenant/space 上下文，不改变全局浏览上下文。

表单持有打开时团队版本，写冲突显示刷新入口；确认影响返回的 revision 作为危险操作提交版本。分页状态分别用于成员、邀请、网盘和活动，默认 50。轮询暂停于后台标签页，写操作成功主动刷新。

新账号本人激活和现有用户邀请与成员列表复用同一服务。激活码仅一次展示，Key 不进入管理员页面。开通成功后邀请失败保留当前交付信息，并提供继续发送邀请入口，不重复开通。

现有个人网盘和旧管理授权中心继续存在。团队未启用时显示诚实的未启用状态。本轮不永久删除团队，不提供开放链接注册、邮件、团队直接填写云密钥或 OneDrive 受管存储。独立 fixture 负责免账号团队演示；真实部署启用不包含在本次操作内。
