# user-directory-ui Specification

## Purpose
定义用户目录的过滤、详情、可见 Key 元数据和账号生命周期操作。明确作用对象与操作影响，保持他人凭据不可见，并通过统一表格留白和按需表单提供可读的管理体验。

## Requirements

### Requirement: 用户筛选和准确的 Key 详情
客户端 SHALL 提供状态、角色、团队和用户/Key 查询，显示真实 Key 元数据计数或明确不可见状态，并打开所选用户详情。

#### Scenario: 查看其他用户
- **WHEN** 用户选择某行的 Key 详情
- **THEN** 展示该用户的可见元数据，不展示他人明文或跳到无关 Key 列表

### Requirement: 确认账号操作影响
客户端 SHALL 使用服务端操作影响与版本执行冻结、解冻、删除归档及恢复，不模拟权限或跳过冲突。

#### Scenario: 删除账号
- **WHEN** 管理员点击删除并归档
- **THEN** 展示停止访问与凭据失效的影响、文件保留说明，已认证管理员输入目标用户名或验证自己的 Key 确认后更新列表

#### Scenario: 接管最后职责
- **WHEN** 最高管理员操作会使团队或网盘没有负责人
- **THEN** 展示后端计算的接管清单，勾选接管并确认名称后可继续；不只显示无法操作的错误

### Requirement: 管理弹窗适应视口

客户端 SHALL 让管理操作表单与记录详情弹层适应视口、保持内外面板宽度一致；管理中心本身 SHALL 使用独立页面。页面与弹层中的表单 SHALL 保留规定留白，不被横向裁切。

#### Scenario: 窄屏管理

- **WHEN** 在 390px 宽窗口打开管理中心并进入操作表单
- **THEN** 页面分类可达，表单弹层只有必要的内部纵向滚动，取消、提交和输入框完整可见

### Requirement: 用户目录表格可读性

客户端 SHALL 在用户目录采用共享表格留白与语义边框；名字、角色状态、团队与 Key 元数据保持可读，操作列仍可达。原用户详情 SHALL 继续绑定选中用户，不另外复制账号管理流程。

#### Scenario: 查看长名称用户行

- **WHEN** 用户目录包含长名称、多行状态和多个操作
- **THEN** 行按内容增高、单元格有足够内边距，完整名称可以从详情读取，深色模式没有高亮横向分隔线

#### Scenario: 用户详情仍保持本人边界

- **WHEN** 用户打开另一用户的 Key 或账号详情
- **THEN** 只显示获授权元数据，不展示他人的明文凭据，切换租户后旧详情被清除

### Requirement: Bounded Key row actions
Key 目录 SHALL 保持内容在各自单元格内，提供单一搜索入口，名称允许多行，次要动作收纳进菜单。菜单 SHALL 保留原权限判定、确认和密钥展示边界。

#### Scenario: Operate a key in a narrow table
- **WHEN** 用户在窄视窗打开 Key 行的更多菜单
- **THEN** 仍可访问被授权的轮转、禁用、启用、吊销、删除和重命名，动作不覆盖身份或状态列
